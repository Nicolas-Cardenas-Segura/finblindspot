# Proposal: Financial Blindspot Detector & Personalised Learning Agent

## Why

Internationally mobile professionals face fragmented pensions, currencies and financial records. Financial Blindspot helps them understand reported financial indicators and missing information without recommending products or directing investments. This is an educational hackathon prototype, not a certification of financial readiness or legal compliance.

## What Changes

- Telegram interviews through Mastra Channels, with a quick partial assessment and a full 15-domain path.
- Validated profile extraction using Nebius, with explicit unknown, skipped, range, currency and period semantics.
- Pure TypeScript calculations and versioned illustrative thresholds for runway, debt exposure, retirement visibility, concentration and cross-border complexity.
- Deterministic report facts and ranking, plus constrained educational wording; every outbound message must pass an independent classifier before delivery.
- Durable private interview state and immutable baseline snapshots, revisits and a labelled six-month simulation.
- A protected read-only report dashboard and public sanitised evaluation evidence; Telegram remains the only interview interface.
- Galtea Endpoint Connections exercising the same application pipeline, with real before/fix/after evidence.

## Capabilities

### New Capabilities
- `conversational-interview`: Private, resumable quick/full Telegram assessment with validated extraction and sensitive-input rejection.
- `calculation-engine`: Currency-aware deterministic indicators, honest incomplete results, illustrative bands and ranked blind spots.
- `advice-guardrail`: Universal fail-closed pre-delivery classification, factual grounding and authenticated evaluation.
- `baseline-comparison`: Durable isolated snapshots, meaningful comparisons and expiring report access.

### Modified Capabilities
None; this is a fresh project.

## Impact

Node.js/TypeScript, Mastra, Nebius and Galtea supply the core sponsor integrations. Railway hosts a single persistent Node process with a volume. LibSQL stores sanitised memory and separate application records. React/Vite provide the read-only dashboard. Vitest verifies pure functions and targeted deterministic safety/access boundaries; model behaviour is evaluated through Galtea rather than mocked or asserted in CI. Norma remains optional and Make is deferred. Model IDs are configurable candidates until authenticated capability checks pass.
